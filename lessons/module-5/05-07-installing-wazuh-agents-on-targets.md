# 05-07: Installing Wazuh Agents on Targets

## What is it used for?
The Wazuh Agent is a lightweight software program installed on the endpoints (virtual machines, containers, or bare-metal servers) you wish to monitor. It acts as the "eyes and ears" of the SIEM. It is used to:
*   **Collect Logs**: Gather system, application, and security logs and forward them securely (via port 1514) to the Wazuh Manager.
*   **Monitor Integrity**: Track critical files and registry keys for unauthorized changes.
*   **Scan for Threats**: Check the local system for known vulnerabilities, missing patches, and rootkits.
*   **Respond**: Execute "Active Response" scripts (e.g., blocking an IP in the local firewall) when commanded by the Manager.

## Techniques
### File Integrity Monitoring (FIM)
The agent calculates cryptographic hashes (MD5, SHA1, SHA256) of specified files and directories. If a file is modified, deleted, or created, the agent immediately alerts the manager. This is a critical technique for detecting web defacements or malicious binary drops.

### Rootkit and Malware Detection
The agent periodically scans the system for hidden processes, hidden files, and inconsistencies in system calls that are characteristic of rootkit infections.

### Deployment Automation
Rather than manually typing commands on dozens of machines, administrators typically use the automated deployment command generated by the Wazuh Dashboard, or they use configuration management tools like Ansible, Chef, or Terraform to deploy agents en masse.

## How those techniques are used
*   **LXC Nodes (e.g., Ubuntu Web Servers)**: The agent runs natively within the Proxmox Linux Container, monitoring the specific applications (like Nginx, Apache, or MySQL) hosted there and reading their specific log files.
*   **Docker Hosts**: Instead of installing an agent *inside* every individual Docker container, the agent is installed on the underlying host. It monitors the Docker daemon and can be configured to read the stdout/stderr logs of the containers.
*   **Windows VMs**: A standard `.msi` installer is used, and the agent hooks directly into the Windows Event Viewer to forward Security, System, and Application logs.

## Commands used

### Method 1: Using the Wazuh Dashboard (Recommended)
The easiest way to install an agent is to use the UI:
1.  Navigate to **Wazuh** -> **Agents** -> **Deploy new agent**.
2.  Select the target OS (e.g., Debian/Ubuntu).
3.  Enter your Wazuh Manager IP address.
4.  Copy the generated command and run it in the terminal of your target node.

### Method 2: Manual CLI Installation (Debian/Ubuntu)
If you need to script the installation manually:

```bash
# 1. Add the Wazuh GPG key
curl -s https://packages.wazuh.com/key/GPG-KEY-WAZUH | gpg --no-default-keyring --keyring gnupg-ring:/usr/share/keyrings/wazuh.gpg --import && chmod 644 /usr/share/keyrings/wazuh.gpg

# 2. Add the repository to apt
echo "deb [signed-by=/usr/share/keyrings/wazuh.gpg] https://packages.wazuh.com/4.x/apt/ stable main" | tee -a /etc/apt/sources.list.d/wazuh.list

# 3. Install the agent and define the manager IP in one step
# Replace 192.168.1.100 with your Manager's IP
WAZUH_MANAGER="192.168.1.100" apt-get update && apt-get install wazuh-agent -y

# 4. Enable and start the service
systemctl daemon-reload
systemctl enable wazuh-agent
systemctl start wazuh-agent
```

### Verification
```bash
# Check the agent status on the target node
systemctl status wazuh-agent

# View the agent log to ensure it successfully connected to the manager
grep "Connected to" /var/ossec/logs/ossec.log
```

## Summary
Without agents, a SIEM is blind. By installing the Wazuh agent on your Proxmox LXC containers and VMs, you enable deep, host-level visibility. The agent's capabilities—ranging from simple log forwarding to advanced File Integrity Monitoring—provide the raw data necessary for the manager to detect, correlate, and alert on complex attacks within your homelab.
